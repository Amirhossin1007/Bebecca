صفحه تنظیمات Xray پیکربندی‌ای را کنترل می‌کند که هسته اجرا می‌کند: اینباندها، خروجی‌ها، مسیریابی، DNS و لاگ‌ها. صفحه لاگ‌های Xray خروجی زنده لاگ را از نودی که انتخاب کرده‌ای نشان می‌دهد.

یک پیکربندی نامعتبر Xray هسته را روی هر نودی که از آن استفاده می‌کند متوقف می‌کند. از پیکربندی فعلی بکاپ بگیر، هر بار یک بخش را تغییر بده و فقط بعد از موفقیت اعتبارسنجی هسته را ری‌استارت کن.

## ویرایش قالب

بخشی را که می‌خواهی ویرایش کنی انتخاب کن:

- **Basics** تنظیمات رایج مثل لاگ، DNS و استراتژی مسیریابی را دربر می‌گیرد.
- **Advanced** ویرایشگر JSON را برای تنظیمات پیشرفته باز می‌کند.
- **Complete template** کل شیء پیکربندی Xray را ویرایش می‌کند.
- **Inbounds**، **Outbounds** و **Routing rules** هر کدام فقط آرایه مربوط به خودشان را در JSON ویرایش می‌کنند.

## لاگ و DNS

- **Log level**، **Access Log**، **Error Log** و **DNS Log** مشخص می‌کنند Xray چه چیزی بنویسد.
- **Auto clear** هر ۱، ۳، ۶ یا ۲۴ ساعت لاگ‌های قدیمی را پاک می‌کند. می‌توان آن را غیرفعال کرد.
- تنظیمات DNS شامل سرورها، قانون‌های دامنه و IP مورد انتظار، کش، fallback، کوئری موازی، استراتژی کوئری و استفاده از فایل hosts سیستم است. سرور DNS اشتباه می‌تواند همه اتصال‌هایی را که به آن وابسته‌اند خراب کند.
- **Fake DNS** برای دامنه‌های مطابق، آدرس‌هایی از یک pool تخصیص می‌دهد.

## مسیریابی، خروجی‌ها و balancerها

- **Routing rules** بر اساس اینباند، مبدا، شبکه، پروتکل، دامنه، IP و پورت تطابق پیدا می‌کنند و ترافیک را به یک خروجی یا balancer می‌فرستند. Xray از اولین قانون مطابق استفاده می‌کند، پس ترتیب را با کنترل‌های بالا و پایین تنظیم کن.
- **Outbounds** را می‌توان دستی اضافه کرد یا یک integration مدیریت‌شده مثل Tor، Windscribe یا Psiphon روی نود ساخته باشد. این خروجی‌ها را با **Check service health** می‌توان بررسی کرد.
- تست خروجی‌ها latency، TCP یا ICMP را اجرا می‌کنند. تست‌های TCP و ICMP به آدرس خروجی نیاز دارند. **Test all** تست را برای همه خروجی‌ها اجرا می‌کند.
- **Balancers** بین تگ‌های خروجی انتخاب‌شده با یک استراتژی و یک fallback تصمیم می‌گیرند.
- **Reverse proxy** یک دستگاه داخلی را از طریق اتصال VLESS به یک سرور عمومی وصل می‌کند. UUID و flow باید در هر دو طرف یکسان باشند.

## تست مسیر

**Test route** از نود انتخاب‌شده می‌پرسد Xray برای یک اتصال ساختگی کدام خروجی را انتخاب می‌کند. مقصد، پورت، شبکه، اینباند و ایمیل کاربر را طوری تنظیم کن که با ترافیک مورد نظرت برابر باشد.

**Test routing rule** یک درخواست واقعی را از طریق یک نمونه موقت Xray روی آن نود اجرا می‌کند، با آدرس تست که وارد می‌کنی.

## ری‌استارت و آمار

- **Restart Core** پیکربندی ذخیره‌شده را اعمال می‌کند. بلافاصله بعد از ری‌استارت، لاگ‌ها را بررسی کن.
- **Statistics** شمارنده‌های آپلود و دانلود اینباندها و خروجی‌ها را نشان می‌دهد.

## لاگ‌های Xray

1. نودی را که می‌خواهی لاگ‌هایش را ببینی انتخاب کن.
2. با اینباند فیلتر کن، یا با UUID، نام کاربری، ایمیل یا تگ اینباند جستجو کن.
3. **Log stream** را دنبال کن. وضعیت سوکت نشان می‌دهد اتصال زنده باز است یا نه.

برای دیدن لاگ‌ها باید دسترسی مشاهده لاگ‌های Xray داشته باشی. با روشن بودن auto-scroll خطوط جدید دنبال می‌شوند؛ آن را خاموش کن تا بتوانی خطوط قدیمی‌تر را بخوانی بدون اینکه نما بپرد.
