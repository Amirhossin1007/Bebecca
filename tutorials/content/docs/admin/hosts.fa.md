هاست تعیین می‌کند هر کلاینت برای یک اینباند چه چیزی دریافت کند. اینباند پروتکل و ترنسپورت را مشخص می‌کند. هاست آدرس و پورت عمومی و تنظیمات اختیاری را تعیین می‌کند. یک اینباند می‌تواند چند هاست داشته باشد، مثلاً برای دامنه‌های مختلف یا آدرس‌های CDN.

صفحه Hosts دو تب دارد:

- **Hosts** نگهدارنده تنظیمات جایگزین هاست‌ها، ترتیب آن‌ها و مسیریابی هر اینباند است.
- **Inbounds** همه اینباندها و گزینه‌های ترنسپورت و امنیت آن‌ها را در یک جا مدیریت می‌کند.

## افزودن هاست

1. وارد **Hosts** شو و روی **Add host** بزن.
2. **Inbound** را انتخاب کن. هاست پروتکل و ترنسپورت را از آن می‌گیرد.
3. **Remark** را وارد کن. این نامی است که کاربر در کلاینتش می‌بیند.
4. یک یا چند مقدار **Address** وارد کن. اگر چند آدرس باشد، به‌صورت چرخشی استفاده می‌شوند.
5. اگر **Port** خالی باشد، پورت اینباند استفاده می‌شود. اگر این هاست سرور دیگری است، پورت مخصوص آن را وارد کن.
6. **Active host** را روشن نگه دار و ذخیره کن.

برای کپی‌کردن هاستی که فقط آدرس یا Remark آن فرق دارد از **Clone** استفاده کن.

## مسیریابی و TLS

فقط فیلدهایی نشان داده می‌شوند که اینباند انتخاب‌شده پشتیبانی می‌کند. فیلد خالی مقدار اینباند را به ارث می‌برد.

- **SNI** نام سرور است. وقتی سرور هاست گواهی با نام دیگری دارد، آن را تنظیم کن.
- **Request Host** هاست HTTP است. چند مقدار را با کاما جدا کن. برای دامنه‌های wildcard از `*` استفاده کن تا رشته تصادفی ساخته شود.
- **Path** معمولاً `/` بماند، مگر اینکه reverse proxy مسیر دیگری بخواهد.
- **Security layer** را فقط وقتی تغییر بده که این هاست لایه امنیتی متفاوتی نسبت به اینباند دارد.
- **ALPN** و **Fingerprint** تنظیمات TLS کلاینت هستند.
- **Allow Insecure** بررسی گواهی را رد می‌کند. فقط وقتی استفاده کن که گواهی مقصد قابل بررسی نیست.
- **Verify peer certificate by name** و **Certificate fingerprint (SHA-256)** گواهی مورد انتظار را ثابت می‌کنند. **Generate automatically** اثرانگشت را می‌سازد.

## گزینه‌های پیشرفته

- **FinalMask** باید خالی باشد یا یک شیء JSON معتبر باشد. قبل از ذخیره بررسی می‌شود.
- **Fragment pattern** از قالب `length,interval,packets` و **Noise pattern** از قالب `packets,delay` استفاده می‌کند. پشتیبانی کلاینت‌ها محدود است، پس قبل از اتکا به آن‌ها کلاینت خودت را بررسی کن.
- **Enable MUX** از کلاینت‌های پشتیبانی‌کننده می‌خواهد اتصال‌ها را چندمسیره کنند.
- **Use random user agent** برای کانفیگ‌های خروجی یک User-Agent رایج تولید می‌کند.
- **Per-host client settings** رفتار کلاینت را فقط برای همین هاست تغییر می‌دهد.

## متغیرهای Remark

Remark می‌تواند متغیرهایی داشته باشد که هنگام ساخت سابسکریپشن برای هر کاربر پر می‌شوند:

`{DATA_LEFT}`, `{DATA_LIMIT}`, `{DATA_USAGE}`, `{DAYS_LEFT}`, `{EXPIRE_DATE}`, `{JALALI_EXPIRE_DATE}`, `{PROTOCOL}`, `{SERVER_IP}`, `{STATUS_EMOJI}`

## تغییرات روی همه سابسکریپشن‌ها اثر می‌گذارد

تغییر هاست روی همه سابسکریپشن‌هایی که از آن استفاده می‌کنند اعمال می‌شود. اگر احتمال استفاده دوباره داری، به جای حذف، هاست را غیرفعال کن. عملیات دسته‌ای می‌تواند چند هاست را یک‌جا فعال، غیرفعال یا حذف کند.

{{< callout type="info" >}}
اگر صفحه Errors گزارش داد اینباند هاست در پیکربندی ذخیره‌شده Xray وجود ندارد، یا اینباند را برگردان یا هاست را به یک اینباند موجود تغییر بده.
