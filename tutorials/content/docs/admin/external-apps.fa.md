با External apps می‌توانی اپلیکیشن‌های کوچک PHP یا استاتیک را بدون وب‌سرور جدا روی ربکا میزبانی کنی. قالب‌های موجود **MirzaBot**، **Faoxima** و یک **پروژه PHP / HTML سفارشی** از یک فایل ZIP هستند.

## پیش‌نیازها

- نصب باینری. External apps با SQLite کار نمی‌کند.
- سرور MySQL یا MariaDB. هر اپلیکیشن دیتابیس اختصاصی خودش را روی همین سرور دارد.
- یک گواهی فعال برای دامنه اپلیکیشن با SNI فعال. اگر گواهی نداری، از پنجره انتشار دکمه **SSL Manager** را باز کن. راهنمای آن را در [گواهی‌های SSL](../ssl-certificates/) ببین.

## انتشار یک اپلیکیشن

1. روی **Deploy application** بزن و یک **Application name** وارد کن.
2. یک **Template** انتخاب کن:
   - **MirzaBot (latest version)** یا **Faoxima (latest source)** برای پروژه‌های ربات تلگرام.
   - **Custom PHP / HTML project** برای آپلود ZIP خودت، یا شروع از پوشه خالی و اضافه کردن فایل بعداً.
3. **Domain and SSL certificate** را انتخاب کن.
4. برای MirzaBot یا Faoxima، **Telegram bot token** و **Telegram admin ID** را وارد کن.
5. گزینه دیتابیس را انتخاب کن:
   - **Create a dedicated MySQL / MariaDB database** برای این اپلیکیشن یک دیتابیس و کاربر اختصاصی می‌سازد. با **Generate all** نام‌ها و رمز به‌صورت خودکار پر می‌شوند. ربکا هم به این دیتابیس دسترسی دارد.
   - اگر از قبل بکاپ SQL اپلیکیشن را داری، گزینه بکاپ را روشن کن و آن را آپلود کن. حداکثر حجم ۳۲ مگابایت است. ربکا آن را در دیتابیس جدا وارد می‌کند و `table.php` را یک بار اجرا می‌کند تا اسکیمای قدیمی به‌روز شود.
6. روی **Deploy** بزن.

{{< callout type="warning" >}}
قبل از بستن پنجره، رمز دیتابیس را ذخیره کن. ربکا آن را برای نمایش بعدی نگه نمی‌دارد.
{{< /callout >}}

## قوانین ZIP پروژه

- حجم آرشیو می‌تواند تا ۳۲ مگابایت فشرده و ۲۵۶ مگابایت پس از استخراج باشد.
- فایل `index.php` یا `index.html` باید در ریشه آرشیو باشد.
- ربکا نوع اجرا را از روی ZIP تشخیص می‌دهد: PHP یا HTML استاتیک. پروژه خالی از نوع استاتیک است.
- می‌توانی بدون ZIP منتشر کنی و فایل‌ها را بعداً از **Files** اضافه کنی.

## نحوه اجرا

- اپلیکیشن‌های استاتیک فرایند پس‌زمینه ندارند.
- اپلیکیشن‌های PHP با رسیدن درخواست، کارگرهای PHP-FPM را راه می‌اندازند و بعد از بیکار شدن متوقف می‌کنند.
- هر اپلیکیشن کاربر Unix و سوکت جدا دارد، بنابراین فایل‌ها و پردازش‌ها بین اپلیکیشن‌ها مشترک نیستند.
- چند ربات تلگرام می‌توانند یک دامنه را به اشتراک بگذارند، به شرط اینکه هر ربات مسیر webhook جدا داشته باشد.

## مدیریت اپلیکیشن

هر اپلیکیشن این گزینه‌ها را دارد:

- **Open** اپلیکیشن را باز می‌کند. برای ربات تلگرام، **Open bot** خود ربات را باز می‌کند.
- **Enable** یا **Disable** اپلیکیشن را روشن یا خاموش می‌کند، بدون اینکه فایل‌هایش حذف شوند.
- **Files** مدیر فایل را باز می‌کند. فایل‌های متنی مثل PHP، HTML، CSS، JavaScript، JSON و SQL در ویرایشگر باز می‌شوند. پوشه‌ها قابل دانلود نیستند.
- **PHP settings** محدودیت منابع، زمان‌ها، حافظه و اندازه آپلود را در محدوده امن تغییر می‌دهد. دستورهای امنیتی و جداسازی قفل هستند. تغییر نامعتبر خودکار برگردانده می‌شود.
- **Settings** مسیریابی، خطاها و کارایی را کنترل می‌کند:
  - **Default document** فایلی است که در ریشه اپلیکیشن نمایش داده می‌شود، مثل `index.php` یا `public/index.php`. این فایل باید از قبل وجود داشته باشد.
  - **Route missing paths to the default document** را برای اپلیکیشن‌های front-controller و SPA روشن کن، یعنی برنامه‌هایی که مسیرهایی مثل `/users/42` را خودشان مدیریت می‌کنند.
  - **Custom 404 document** یک فایل HTML اختیاری است، مثل `errors/404.html`.
  - **Request body limit** بزرگ‌ترین درخواست یا آپلود پذیرفته‌شده را از ۱ تا ۳۲ مگابایت تعیین می‌کند.
  - **Static asset cache** مدت کش مرورگر برای CSS، JavaScript، تصویر و فایل‌های استاتیک را بر حسب ثانیه تعیین می‌کند. عدد ۰ کش مرورگر را غیرفعال می‌کند. HTML همیشه دوباره بررسی می‌شود.
- **Download SQL backup** دیتابیس اپلیکیشن را خروجی می‌گیرد.
- **Update** برای MirzaBot موجود است. فایل‌های اپلیکیشن را جایگزین می‌کند و `config.php`، دیتابیس و رازهای ربکا را نگه می‌دارد. وابستگی‌های Composer با نسخه ثابت و `table.php` قبل از فعال شدن فایل‌های جدید اجرا می‌شوند.
- **Delete** فایل‌های اپلیکیشن را حذف می‌کند. می‌توانی دیتابیس اختصاصی و کاربر آن را نگه داری. گواهی SSL همیشه نگه داشته می‌شود.

{{< callout type="info" >}}
قبل از به‌روزرسانی یا حذف اپلیکیشن، بکاپ SQL آن را دانلود کن و از داشبورد یک بکاپ از پنل بگیر.
{{< /callout >}}
