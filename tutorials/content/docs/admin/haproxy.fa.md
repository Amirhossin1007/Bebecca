Rebecca می‌تواند HAProxy را روی نودهای انتخاب‌شده اجرا کند و چند مقصد را پشت یک پورت عمومی TCP قرار دهد. HAProxy ابتدای هر اتصال را می‌خواند، SNI یا HTTP Host یا HTTP Path را تشخیص می‌دهد و همان جریان TCP را به اینباند Xray، سرویس خارجی یا وب‌سایت درست می‌فرستد. ترافیک Xray در این مسیر رمزگشایی نمی‌شود.

{{< callout type="warning" >}}
بعد از فعال‌شدن تنظیمات، پورت عمومی در اختیار HAProxy است. Xray، Nginx، Apache، OpenVPN یا برنامه دیگری نباید روی همان آدرس و پورت درحال Listen باشد. هر اینباند Xray انتخاب‌شده نیز باید پورت مقصد جداگانه‌ای داشته باشد که با پورت عمومی HAProxy فرق کند.
{{< /callout >}}

## ساختار تنظیمات

هر تنظیم HAProxy چهار لایه دارد:

1. **Configuration** تنظیمات پیشرفته مشترک و یک یا چند نود تارگت را نگه می‌دارد.
2. **Target** همان نود Rebecca است که این تنظیمات روی آن اجرا می‌شود.
3. **Listener** یک آدرس و پورت عمومی TCP روی آن نود است، مثلاً `0.0.0.0:443`.
4. داخل هر Listener چند **Route** و در صورت نیاز چند **Website** قرار می‌گیرد. Route به اینباند Xray یا یک سرویس TCP خارجی می‌رود. Website هم ترافیک عادی HTTP یا TLS را پاسخ می‌دهد.

در پنل می‌شود چند Configuration جدا ساخت. هر نود در یک زمان فقط می‌تواند عضو یکی از آن‌ها باشد، ولی یک Configuration می‌تواند نودهای زیادی داشته باشد. روی هر Target حداکثر ۱۶ Listener قابل ساخت است؛ بنابراین همان نود می‌تواند هم‌زمان پورت‌های `443` و `550` و چند پورت TCP دیگر را مدیریت کند. مسیرها و وب‌سایت‌های هر پورت مستقل هستند.

Rebecca Node قبل از جایگزین‌کردن فایل فعال، کانفیگ تولیدشده را با `haproxy -c` بررسی می‌کند. نصب و آپدیت Rebecca Node بسته HAProxy را هم خودکار نصب می‌کند. HAProxy داخل Image داکر نود هم وجود دارد. اگر یک نود قدیمی پیام نبودن HAProxy را نشان داد، پیش از فعال‌کردن تنظیمات، نود را آپدیت کنید.

## پیش از شروع

- پنل مستر و تمام نودهای تارگت را به نسخه‌ای آپدیت کنید که قابلیت HAProxy را دارد.
- با `ss -lntp` روی هر نود مطمئن شوید پورت عمومی موردنظر آزاد است.
- پورت TCP عمومی را در فایروال سیستم و فایروال Provider باز کنید.
- برای هر اینباند Xray یک پورت Backend جدا بگذارید. این پورت نباید با پورت عمومی HAProxy یکسان باشد.
- از قبل مشخص کنید هر اتصال با چه چیزی تشخیص داده می‌شود. SNI یا Host یا Path یکتا بهترین انتخاب است.
- یک مسیر مدیریتی مطمئن مثل SSH برای نود نگه دارید تا اشتباه در Listener یا فایروال دسترسی شما را قطع نکند.
- بار اول Configuration را در حالت غیرفعال ذخیره کنید، خروجی **Editor** را ببینید و بعد آن را فعال کنید.

## راه‌اندازی سریع: چند سرویس روی پورت ۴۴۳

در این مثال سه نوع ترافیک از پورت `443` عبور می‌کنند:

| ترافیک ورودی | روش تشخیص | مقصد |
| --- | --- | --- |
| VLESS Reality | SNI برابر `edge.example.com` | اینباند Xray روی `127.0.0.1:5424` |
| VLESS WebSocket | HTTP Path برابر `/ws-main` | اینباند Xray روی `127.0.0.1:5425` |
| HTTPS عادی | SNI برابر `www.example.com` | یک وب‌سایت با گواهی SSL موجود در پنل |

1. دو اینباند Xray را روی نود آماده کنید. پورت، Tag و مقدار تشخیص آن‌ها باید با هم فرق کند.
2. صفحه **HAProxy** را باز کنید و روی **ساخت HAProxy** بزنید.
3. نام Configuration را وارد کنید. هنگام ساخت نسخه اولیه، گزینه **فعال** را خاموش نگه دارید.
4. نود را انتخاب کنید و **افزودن تارگت** را بزنید.
5. داخل `listener-1` مقدار **آدرس گوش‌دادن** را روی `0.0.0.0` نگه دارید و **پورت عمومی** را `443` بگذارید.
6. اینباند Reality را از **اینباند سازگار Xray** انتخاب کنید. Matcher مربوط به SNI آن را بردارید و **افزودن اینباند** را بزنید.
7. اینباند WebSocket را با Matcher مربوط به `/ws-main` اضافه کنید.
8. **افزودن وب‌سایت** را بزنید. وب‌سایت را فعال کنید، `www.example.com` را وارد کنید، **گواهی موجود در SSL پنل** را انتخاب کنید و گواهی فعال همان دامنه را بردارید.
9. یکی از قالب‌های داخلی، TemplateMo یا ZIP آپلودشده را انتخاب کنید.
10. تب **ادیتور** را باز کنید. Rebecca فرم را اعتبارسنجی می‌کند و فایل نهایی هر نود را نشان می‌دهد.
11. به تب **فرم** برگردید، Configuration را فعال کنید و **ذخیره** را بزنید.

هر مسیر را جداگانه تست کنید. بازشدن وب‌سایت فقط مسیر وب‌سایت را ثابت می‌کند و به‌تنهایی به معنی سالم‌بودن مسیرهای VLESS نیست.

## HAProxy چطور مقصد را تشخیص می‌دهد؟

تمام Listenerهای تولیدشده در TCP mode اجرا می‌شوند. HAProxy تا سقف زمان تعیین‌شده در **Inspection delay** منتظر می‌ماند و بایت‌های قابل‌مشاهده ابتدای اتصال را بررسی می‌کند.

| روش تشخیص | چیزی که HAProxy می‌خواند | کاربرد معمول |
| --- | --- | --- |
| `sni` | نام دامنه داخل TLS ClientHello | TLS، Reality، وب‌سایت HTTPS و سرویس خارجی مبتنی بر TLS |
| `http_host` | هدر `Host` در HTTP | انتقال‌های HTTP ساده با دامنه‌های متفاوت |
| `http_path` | ابتدای Path درخواست HTTP | WebSocket، HTTPUpgrade، SplitHTTP یا انتقال HTTP با Path یکتا |
| `default` | هیچ امضایی بررسی نمی‌شود؛ ترافیک Matchنشده را می‌گیرد | یک پروتکل رمز‌شده خام یا یک سرویس fallback |

برای Routeهای Xray و External، بررسی SNI باعث Terminateشدن TLS نمی‌شود. HAProxy فقط ClientHello را می‌خواند و اتصال دست‌نخورده را تحویل Backend می‌دهد. Website فرق دارد؛ وب‌سرور داخلی نود TLS را با گواهی انتخاب‌شده برای همان سایت Terminate می‌کند.

داخل هر Listener مقدار Matcherها باید یکتا باشد و فقط یک Route از نوع `default` مجاز است. دامنه یک Website مبتنی بر TLS نیز نباید با SNI یک Route روی همان Listener یکسان باشد، چون هر دو یک اتصال را Match می‌کنند.

## اینباندهای واجد شرایط {#eligible-inbounds}

فهرست اینباندها از کانفیگ واقعی Xray همان نود تارگت ساخته می‌شود. هر اینباند باید Tag غیرخالی، پورت معتبر و Matcher قابل‌استفاده داشته باشد. Rebecca این اطلاعات را از `streamSettings` می‌خواند.

| Transport یا Security اینباند | گزینه‌ای که Rebecca نشان می‌دهد | شرط لازم |
| --- | --- | --- |
| WebSocket، HTTPUpgrade، SplitHTTP یا انتقال HTTP ساده | `http_path` | Path در تنظیمات Transport خالی نباشد. |
| انتقال HTTP ساده با Host یا `headers.Host` | `http_host` | Host معتبر و یکتا باشد. |
| انتقال TLS با Host در تنظیمات Transport | `sni` | Host معتبر و یکتا باشد. |
| TLS با `tlsSettings.serverName` | `sni` | Server name معتبر و یکتا باشد. |
| Reality با `realitySettings.serverNames` | برای هر Server name یک گزینه `sni` | SNIای را انتخاب کنید که کلاینت واقعاً ارسال می‌کند. |
| اینباندی غیر از Shadowsocks که هیچ‌کدام از موارد بالا را ندارد | `default` | تنها Route پیش‌فرض آن Listener باشد. |
| Shadowsocks | Matcher مبتنی بر Path | Transport باید Path غیرخالی داشته باشد. بدون Path در فهرست نمایش داده نمی‌شود. |

{{< callout type="info" >}}
نبودن Path یا SNI همیشه به معنی حذف اینباند نیست. اینباندهای غیر Shadowsocks ممکن است به‌صورت `default` نمایش داده شوند، اما روی هر Listener فقط یک مقصد پیش‌فرض قابل استفاده است. قانون Shadowsocks سخت‌گیرانه‌تر است و تا زمانی که Transport آن Path نداشته باشد قابل انتخاب نیست.
{{< /callout >}}

دو اتصال رمز‌شده خام که SNI یا Host یا Path قابل‌مشاهده ندارند، از دید HAProxy یکسان هستند. نمی‌شود هر دو را با دو Route جدا روی یک پورت تشخیص داد. یکی را به Listener دیگری ببرید یا فقط یکی را به‌عنوان Route پیش‌فرض انتخاب کنید. عوض‌کردن نام Route چیزی به ترافیک اضافه نمی‌کند و مشکل تشخیص را حل نمی‌کند.

### چرا یک اینباند در فهرست نیست؟

موارد زیر را روی همان نود تارگت بررسی کنید:

1. فیلد `tag` اینباند خالی نباشد.
2. پورت بین `1` و `65535` باشد و با پورت عمومی Listener فرق کند.
3. اگر اینباند Shadowsocks است، Transport آن Path داشته باشد.
4. SNI یا Host یا Path در کانفیگ تولیدشده Xray همین نود وجود داشته باشد، نه اینکه فقط در فرم Host یا Service ثبت شده باشد.
5. همان اینباند قبلاً به Listener اضافه نشده باشد.
6. کارت Target باز باشد. اطلاعات Candidate هنگام فعال‌بودن **نمایش تنظیمات** دریافت می‌شود.

## مرجع کامل تب فرم

### فیلدهای Configuration

| فیلد | کاربرد |
| --- | --- |
| **نام پیکربندی** | نام داخلی در پنل است. این مقدار دامنه، Tag اینباند یا نام Frontend نهایی HAProxy را تغییر نمی‌دهد. حداکثر ۱۲۸ کاراکتر مجاز است. |
| **فعال** | کانفیگ تولیدشده را روی تمام Targetهای انتخاب‌شده اعمال می‌کند. برای نگه‌داشتن Draft بدون اجرای HAProxy، آن را خاموش بگذارید. |
| **نود تارگت** | نودی را انتخاب می‌کند که این تنظیمات روی آن ساخته می‌شود. نود غیرفعال برچسب دارد و قابل انتخاب نیست. نودی که عضو Configuration دیگری است نیز آزاد نیست. |
| **افزودن تارگت** | یک کارت Target با یک Listener اولیه می‌سازد. هر Configuration حداقل یک و حداکثر ۲۵۶ Target دارد. |
| **نام قالب**، **ZIP** و **آپلود** | یک قالب استاتیک قابل‌استفاده مجدد به پنل اضافه می‌کند. ZIP باید `index.html` داشته باشد، فقط فایل‌های استاتیک امن داشته باشد و حداکثر ۳۲ مگابایت باشد. حجم Extractشده نیز حداکثر ۱۲۸ مگابایت است. |

### کنترل‌های کارت Target

| گزینه | کاربرد |
| --- | --- |
| **نمایش تنظیمات** | کارت همین نود را باز یا بسته می‌کند. بستن کارت فقط ظاهر UI را جمع می‌کند و نود را غیرفعال نمی‌کند. Targetهای Cloneشده برای کوتاه‌ماندن صفحه به‌صورت بسته ساخته می‌شوند. |
| **قالب تصادفی TemplateMo** | مربوط به عملیات Clone است. اگر فعال باشد، برنامه تا جای ممکن برای Websiteهای TemplateMo هر نود مقصد قالب متفاوتی از Catalog انتخاب می‌کند. بقیه تنظیمات تغییری نمی‌کنند. |
| **کلون روی تمام نودهای آزاد** | تمام Listenerها، Routeها و Websiteهای این Target را روی نودهای فعال و آزاد همین Configuration کپی می‌کند. |
| **حذف تارگت** | نود را از Draft حذف می‌کند. این تغییر بعد از ذخیره به نود می‌رسد. |

Clone با اینباند مشابهِ ظاهری انجام نمی‌شود. هر Route از نوع Xray باید روی نود مقصد همان Tag و همان نوع و مقدار Matcher را داشته باشد. Rebecca پورت Backend را از کانفیگ Xray خود نود مقصد جایگزین می‌کند. اگر حتی یکی از اینباندهای لازم وجود نداشته باشد، کل Target آن نود ساخته نمی‌شود و پیام هشدار نام نود و اینباند را می‌نویسد. نودهای Disabled نیز Clone نمی‌شوند.

### فیلدهای Listener

| فیلد | کاربرد |
| --- | --- |
| **نام لیسنر** | برچسب داخلی Listener است و حداکثر ۶۴ کاراکتر دارد. مقدار چندخطی مجاز نیست. |
| **آدرس گوش‌دادن** | آدرسی که HAProxy روی نود Bind می‌کند. `0.0.0.0` تمام آدرس‌های IPv4 را می‌گیرد، `::` برای IPv6 است و یک IP مشخص Listener را به همان آدرس نود محدود می‌کند. |
| **پورت عمومی** | پورت TCPای است که کلاینت به آن وصل می‌شود. بازه معتبر `1` تا `65535` است. یک آدرس و پورت روی همان Target نباید تکرار شود. |
| **نمایش تنظیمات پورت** | کارت همین Listener را باز یا بسته می‌کند. بستن کارت فقط فرم را جمع می‌کند و پورت از کانفیگ حذف نمی‌شود. |
| **پذیرش PROXY protocol ورودی** | از کلاینت یا Load balancer بالادستی یک Header معتبر PROXY protocol می‌خواهد. برای اتصال مستقیم کاربران اینترنت خاموش بماند. روشن‌کردن آن برای کلاینت عادی باعث قطع اتصال می‌شود. |
| **اینباند سازگار Xray** | فقط Candidateهای تشخیص‌داده‌شده روی همین نود را نشان می‌دهد. Tag، Protocol، Network و Matcher هر گزینه در فهرست نوشته شده است. |
| **افزودن اینباند** | Candidate انتخاب‌شده را به Routeای با مقصد `127.0.0.1` و پورت واقعی اینباند تبدیل می‌کند. اطلاعات Backend از کانفیگ نود می‌آید و دستی نیست. |
| **افزودن سرویس خارجی** | یک Backend TCP دستی برای OpenConnect، OpenVPN TCP، سرویس لوکال یا هر مقصد غیر Xray می‌سازد. |
| **افزودن پورت / لیسنر** | یک آدرس و پورت عمومی مستقل دیگر به همین Target اضافه می‌کند. Routeها و Websiteهای Listener قبلی خودکار کپی نمی‌شوند. |
| **حذف لیسنر** | Listener را از Draft حذف می‌کند. هر Target باید حداقل یک Listener داشته باشد. |

هر Target حداکثر ۱۶ Listener دارد. هر Listener هم حداکثر ۳۲ Route و ۱۶ Website می‌پذیرد و باید دست‌کم یک Route یا یک Website فعال داشته باشد.

### کارت Route از نوع Xray

فیلدهای این کارت به‌جز دکمه حذف فقط‌خواندنی هستند، چون مقصد باید با کانفیگ واقعی Xray همان نود یکسان بماند.

| چیزی که می‌بینید | معنی |
| --- | --- |
| نام Route | Tag اینباند Xray است. |
| `sni` یا `http_host` یا `http_path` یا `default` | Matcher دقیقی است که HAProxy استفاده می‌کند. |
| `127.0.0.1:port` | آدرس Backend و پورت واقعی اینباند روی این Target است. |
| Protocol | پروتکلی است که کانفیگ Xray نود گزارش کرده است. |

### فیلدهای External service

| فیلد | کاربرد |
| --- | --- |
| **نام مسیر** | نام داخلی یکتا با حداکثر ۶۴ کاراکتر. |
| **هاست مقصد** | IP یا Hostnameای که از نود قابل دسترسی است. برای سرویسی روی همان نود از `127.0.0.1` استفاده کنید. |
| **پورت مقصد** | پورت TCP سرویس مقصد. این مقدار نباید دوباره به همان پورت Listener روی Loopback اشاره کند. |
| **روش تشخیص** | یکی از `sni`، `http_host`، `http_path` یا `default`. روشی را انتخاب کنید که کلاینت واقعی ارسال می‌کند. |
| **مقدار تشخیص** | دامنه یا Path مورد Match است. برای `default` غیرفعال می‌شود. Path باید با `/` شروع شود و حداکثر ۵۱۲ کاراکتر دارد. |

نام Route و جفت Matcher باید داخل Listener یکتا باشد. Backend host باید معتبر باشد و پورت مقصد در بازه `1` تا `65535` قرار بگیرد.

## وب‌سایت روی پورت مشترک

Website اختیاری است. وقتی یک مرورگر عادی به همان پورت می‌آید، می‌توانید به‌جای قطع اتصال یک صفحه واقعی نشان دهید و ترافیک Xray یا سرویس‌های TCP را همچنان به Route خودشان بفرستید. نود فایل‌های استاتیک را روی Unix socket داخلی سرو می‌کند و HAProxy به همان Socket وصل می‌شود؛ در نتیجه پورت عمومی دیگری برای وب‌سایت باز نمی‌شود.

### فیلدهای Website

| فیلد | کاربرد |
| --- | --- |
| کلید روشن و خاموش Website | سایت را بدون پاک‌کردن فیلدهایش فعال یا غیرفعال می‌کند. سایت خاموش در کانفیگ نهایی قرار نمی‌گیرد. |
| **وب‌سایت پیش‌فرض HTTP/HTTPS** | فقط روی اولین Website دیده می‌شود. ترافیک HTTP و HTTPSای که با Route یا Hostname دیگری Match نشده باشد به این سایت می‌رود. اگر Listener یک Route از نوع `default` داشته باشد، این گزینه غیرفعال است. |
| **نمایش تنظیمات** | کارت همین Website را بدون فعال یا غیرفعال‌کردن سایت باز و بسته می‌کند. |
| **نام وب‌سایت** | برچسب داخلی با حداکثر ۶۴ کاراکتر. اگر خالی باشد، Rebecca از Hostname استفاده می‌کند. |
| **دامنه / SNI** | برای HTTP با Host و برای TLS با SNI Match می‌شود. برای Website پیش‌فرض اختیاری و برای سایر سایت‌های TLS اجباری است. وقتی Website پیش‌فرض فعال باشد، بقیه سایت‌ها نیز برای تفکیک به Hostname نیاز دارند. |
| **گواهی TLS** | بین HTTP ساده، گواهی self-signed خودکار، گواهی مدیریت‌شده پنل یا فایل گواهی موجود روی نود انتخاب می‌کند. |
| **منبع قالب** | صفحه داخلی سبک، TemplateMo یا ZIP آپلودشده را انتخاب می‌کند. |
| **روش انتخاب قالب** | برای TemplateMo فقط یکی از دو روش Catalog یا لینک صفحه را فعال می‌کند. این دو حالت هم‌زمان قابل استفاده نیستند. |
| **قالب** | قالب موجود در Catalog یا قالب آپلودشده را انتخاب می‌کند. |
| **لینک صفحه TemplateMo** | لینکی مثل `https://templatemo.com/tm-632-machina` می‌گیرد. Rebecca لینک دانلود درست را تولید می‌کند و نود ZIP را دانلود و Cache می‌کند. |
| **نمایش پیش‌نمایش قالب** | صفحه TemplateMo یا Preview موجود را باز می‌کند. این دکمه چیزی را ذخیره یا منتشر نمی‌کند. |
| **HTML سفارشی ۴۰۴** | پاسخ Not Found را فقط برای همین Website عوض می‌کند. حداکثر حجم ۶۴ کیلوبایت است. برای پاسخ عادی فایل استاتیک، خالی بگذارید. |

لینک TemplateMo باید HTTPS، روی Host خود `templatemo.com` و به شکل `/tm-NNN-name` باشد. فایل آپلودی نیز باید `index.html` داشته باشد. PHP، WordPress، دیتابیس و کد Server-side در این بخش اجرا نمی‌شوند؛ این قابلیت فقط فایل استاتیک سرو می‌کند.

### حالت‌های گواهی TLS

| حالت | رفتار و کاربرد |
| --- | --- |
| **بدون TLS (HTTP ساده)** | HTTP عادی را سرو می‌کند. Hostname اختیاری است. اگر Hostname خالی باشد، اولین سایت HTTP سازگار می‌تواند ترافیک HTTPای را بگیرد که Route قبلی آن را Match نکرده است. |
| **گواهی self-signed خودکار** | نود برای Hostname گواهی می‌سازد و آن را Cache می‌کند. مرورگر به‌خاطر معتبرنبودن CA هشدار می‌دهد. برای تست مناسب است، نه وب‌سایت عمومی معمولی. |
| **گواهی موجود در SSL پنل** | یکی از گواهی‌های فعال مدیریت‌شده توسط Rebecca را انتخاب می‌کند. گواهی باید Hostname وب‌سایت را پوشش دهد. پنل هنگام Sync، محتوای PEM را به همان نود می‌فرستد. |
| **مسیر گواهی روی نود** | مسیر مطلق Fullchain و Private key روی همان نود را می‌گیرد؛ مثلاً `/etc/ssl/example/fullchain.pem` و `/etc/ssl/example/privkey.pem`. Process نود باید اجازه خواندن این فایل‌ها را داشته باشد. |

برای هر Hostname یک Website جدا بسازید. Website پیش‌فرض هم HTTP ساده و هم HTTPS بدون Match را سرو می‌کند؛ اگر حالت TLS انتخاب نشده باشد، بخش HTTPS آن از گواهی self-signed ذخیره‌شده روی نود استفاده می‌کند. سایت‌های TLS نام‌دار پیش از fallback با SNI تفکیک می‌شوند. مسیر Custom certificate مربوط به فایل‌سیستم هر نود است؛ قبل از Clone مطمئن شوید همان فایل‌ها روی تمام نودهای مقصد وجود دارند.

## مرجع کامل تب پیشرفته

مقدارهای پیش‌فرض برای استفاده معمول مناسب هستند. هر بار فقط یک مقدار را عوض کنید و بعد خروجی Editor و ترافیک واقعی را بررسی کنید.

| فیلد | پیش‌فرض | بازه مجاز | کاربرد |
| --- | ---: | ---: | --- |
| **حداکثر اتصال‌ها** | `8192` | `128` تا `1,000,000` | مقدار `maxconn` را تعیین می‌کند. بالا‌بردن آن به File descriptor، RAM و ظرفیت Kernel کافی روی همه Targetها نیاز دارد. |
| **زمان تشخیص (میلی‌ثانیه)** | `5000` | `100` تا `30000` | حداکثر زمان انتظار برای رسیدن ClientHello یا بایت‌های HTTP کافی است. مقدار خیلی کم کلاینت کند را اشتباه تشخیص می‌دهد و مقدار زیاد اتصال مبهم را دیرتر می‌فرستد. |
| **مهلت اتصال (میلی‌ثانیه)** | `5000` | `100` تا `60000` | زمانی است که HAProxy برای برقراری اتصال با Backend فرصت دارد. |
| **مهلت کلاینت (ثانیه)** | `3600` | `1` تا `86400` | Timeout بی‌کاری سمت کلاینت در جریان TCP Proxyشده است. |
| **مهلت سرور (ثانیه)** | `3600` | `1` تا `86400` | Timeout بی‌کاری سمت Backend است. Tunnel طولانی ممکن است به مقدار بیشتری نیاز داشته باشد. |
| **تلاش مجدد اتصال** | `3` | `0` تا `10` | تعداد تلاش مجدد برای وصل‌شدن به Backend است و Session برقرارشده کاربر را از اول اجرا نمی‌کند. |
| **فعال‌سازی بررسی سلامت TCP** | روشن | روشن یا خاموش | TCP check را به Backendهای Route اضافه می‌کند. اتصال TCP موفق یعنی پورت در دسترس است و به معنی Login موفق در پروتکل نیست. |
| **فاصله بررسی (میلی‌ثانیه)** | `2000` | `100` تا `60000` | فاصله بین TCP checkهای Backend. |
| **سالم پس از موفقیت** | `2` | `1` تا `10` | تعداد Check موفق پشت‌سرهم تا Backend دوباره سالم شناخته شود. |
| **قطع پس از خطا** | `3` | `1` تا `10` | تعداد Check ناموفق پشت‌سرهم تا Backend Down شناخته شود. |
| **سطح لاگ** | `info` | `silent`، `emerg`، `alert`، `crit`، `err`، `warning`، `notice`، `info`، `debug` | حجم خروجی HAProxy در Log سرویس Rebecca Node را تعیین می‌کند. `debug` شلوغ است و بهتر است فقط هنگام عیب‌یابی موقت استفاده شود. |
| **TCP keepalive** | روشن | روشن یا خاموش | Keepalive سمت کلاینت و Backend را در HAProxy فعال می‌کند. |
| **عدم ثبت اتصال‌های خالی** | روشن | روشن یا خاموش | اتصال‌هایی را که بدون ارسال داده مفید بسته می‌شوند از Log حذف می‌کند. برای بررسی Scan یا قطع زودهنگام می‌توان موقتاً خاموشش کرد. |

## تب ادیتور و ذخیره‌کردن

با بازکردن تب **ادیتور**، Draft برای اعتبارسنجی و تولید به Backend فرستاده می‌شود. Editor فقط‌خواندنی است و فایل نهایی هر Target را جدا نشان می‌دهد. بعد از تغییر فرم، **Refresh** را بزنید.

قبل از فعال‌کردن Draft این موارد را در خروجی ببینید:

- آدرس و پورت هر خط `bind` درست باشد.
- هر `acl` همان SNI یا Host یا Path موردنظر را داشته باشد.
- هر `use_backend` به Route درست اشاره کند.
- `default_backend` فقط وقتی وجود داشته باشد که عمداً Route پیش‌فرض ساخته‌اید.
- مقدار `server target` برای Xray، پورت Backend درست همان نود را نشان دهد.

دکمه **ذخیره** Draft را ثبت می‌کند و Sync نود را در صف می‌گذارد. Configuration فعال وقتی روی نود اعمال می‌شود که نود Runtime جدید را بگیرد. اگر Configuration را خاموش و ذخیره کنید، Runtime HAProxy و وب‌سرورهای داخلی مربوط به آن روی Target متوقف می‌شوند.

## کلون‌کردن یک Target روی چند نود

اول یک Target مبنا را کامل تنظیم و تست کنید. سپس:

1. با **نمایش تنظیمات** کارت آن نود را باز کنید.
2. اگر می‌خواهید قالب HTML نودها فرق کند، **قالب تصادفی TemplateMo** را روشن کنید.
3. **کلون روی تمام نودهای آزاد** را بزنید.
4. پیام نتیجه را بخوانید. تعداد نودهای اضافه‌شده و نودهای Skipشده در آن نوشته می‌شود.
5. قبل از Save چند Target ساخته‌شده را باز کنید و پورت‌ها، Routeها، گواهی‌ها و Websiteها را ببینید.

Clone تمام Listenerها را کپی می‌کند. اگر Target مبنا دو پورت `443` و `550` داشته باشد، هر دو روی نودهای پذیرفته‌شده ساخته می‌شوند. تصادفی‌کردن فقط انتخاب TemplateMo را عوض می‌کند و قالب Built-in یا ZIP آپلودشده دست‌نخورده می‌ماند. وقتی این گزینه روشن باشد، لینک مستقیم TemplateMo نیز روی نود مقصد با یک انتخاب از Catalog جایگزین می‌شود.

نودی که Disabled است، عضو Configuration دیگری است، اطلاعاتش قابل دریافت نیست یا یکی از Tag و Matcherهای لازم Xray را ندارد، Skip می‌شود. کارت Targetهای ساخته‌شده ابتدا بسته است.

## پشتیبانی از پروتکل‌های غیر Xray

این قابلیت TCP را Route می‌کند. پشتیبانی هر پروتکل به TCPبودن و داشتن Matcher قابل‌اعتماد بستگی دارد.

| پروتکل یا سرویس | پشتیبانی | روش پیشنهادی |
| --- | --- | --- |
| OpenVPN TCP | بله | Listener جدا یا تنها External route از نوع `default`. ترافیک معمول OpenVPN Path یا SNI قابل‌اتکا ندارد. |
| OpenVPN UDP | خیر | Listenerهای TCP در HAProxy نمی‌توانند UDP را دریافت یا تفکیک کنند. |
| WireGuard | خیر | WireGuard از UDP استفاده می‌کند. پورت UDP آن را خارج از این Configuration نگه دارید. |
| L2TP/IPsec | خیر | L2TP/IPsec به پورت‌های UDP مثل `1701` و `500` و `4500` وابسته است. |
| OpenConnect یا Cisco AnyConnect روی TCP/TLS | معمولاً بله | به‌صورت External service اضافه کنید. فقط وقتی SNI انتخاب کنید که کلاینت واقعاً Hostname متفاوت بفرستد؛ در غیر این صورت Listener جدا یا Route پیش‌فرض لازم است. شتاب‌دهی UDP در این قابلیت نیست. |
| SSH، دیتابیس یا سرویس TCP خام | بله | مگر اینکه پروتکل امضای SNI یا HTTP پشتیبانی‌شده داشته باشد، Listener جدا یا Route پیش‌فرض استفاده کنید. |
| سرویس HTTP یا HTTPS | بله | `http_host` یا `http_path` یا `sni` یا قابلیت Website داخلی را استفاده کنید. |

HAProxy از روی نام Route یا پورت Backend نمی‌تواند نوع پروتکل را حدس بزند. دو جریان رمز‌شده که بایت قابل‌تشخیص متفاوتی ندارند، باید روی دو پورت عمومی جدا قرار بگیرند.

## چند چیدمان کاربردی

### دو پورت عمومی روی هر Target

- Listener با نام `public-443`: آدرس `0.0.0.0:443` برای Routeهای SNI و Path مربوط به Xray و چند Website از نوع HTTPS.
- Listener با نام `vpn-550`: آدرس `0.0.0.0:550` برای یک External route از نوع `default` که به OpenVPN TCP می‌رود.

برای ساخت پورت دوم، داخل کارت Target روی **افزودن پورت / لیسنر** بزنید. داخل فیلد **پورت عمومی** دو عدد وارد نکنید. هر Listener دقیقاً یک پورت و جدول Route مستقل دارد.

### چند وب‌سایت TLS روی پورت ۴۴۳

یک Listener روی `443` بسازید. برای هر Hostname یک Website اضافه کنید و حالت گواهی آن را انتخاب کنید. HAProxy با SNI مقصد درست را پیدا می‌کند. Hostnameها باید یکتا باشند و با SNI اینباند Xray یا External route تداخل نداشته باشند.

### VLESS WebSocket کنار یک وب‌سایت عادی

برای WebSocket یک Path یکتا مثل `/private-ws` بگذارید و آن را به‌عنوان Route از نوع `http_path` اضافه کنید. سپس یک Website از نوع HTTP ساده بسازید و در صورت نیاز Hostname بدهید. Routeها پیش از Website بررسی می‌شوند؛ بنابراین `/private-ws` به Xray می‌رود و درخواست HTTP دیگری که با سایت سازگار است صفحه را می‌گیرد.

### یک سرویس TCP مبهم به‌عنوان fallback

ابتدا تمام Routeهای قابل‌تشخیص SNI و Host و Path را اضافه کنید. بعد سرویس خام را به‌عنوان تنها External route از نوع `default` بگذارید. تمام ترافیک Matchنشده به آن Backend می‌رود. فقط زمانی این کار را انجام دهید که فرستادن همه اتصال‌های ناشناخته به همان سرویس تصمیم عمدی شما باشد.

## عیب‌یابی {#troubleshooting}

| نشانه | مواردی که باید بررسی شود |
| --- | --- |
| هیچ نودی در Selector نیست | نود ممکن است Disabled یا Deleted باشد، قبلاً در همین Draft انتخاب شده باشد یا عضو Configuration دیگری باشد. |
| اینباند Xray دیده نمی‌شود | Tag، پورت، تخصیص نود و Matcher را ببینید. Shadowsocks به Path نیاز دارد. اینباند خام دیگری شاید فقط به‌صورت `default` ظاهر شود. |
| Save خطای Duplicate matcher می‌دهد | دو Route روی یک Listener نوع و مقدار Matcher یکسان دارند. تنظیم Transport را عوض کنید یا یکی را به Listener دیگری ببرید. |
| Save بیش از یک Default را رد می‌کند | یا یک Route پیش‌فرض نگه دارید یا اولین Website را پیش‌فرض کنید. برای مقصدهای دیگر Matcher قابل‌مشاهده یا پورت عمومی جدا بسازید. |
| Hostname سایت با Route تداخل دارد | یک SNI هم‌زمان برای Website و Route از نوع Xray یا External استفاده شده است. Hostnameها را جدا کنید. |
| گواهی Managed رد می‌شود | گواهی باید در بخش SSL پنل Active باشد و Hostname وب‌سایت را پوشش دهد. هم دامنه انتخاب‌شده و هم فایل‌های گواهی را بررسی کنید. |
| Custom certificate روی یکی از Cloneها خطا دارد | Path سفارشی مربوط به فایل‌سیستم هر نود است. فایل‌ها و Permission را روی همان نود اصلاح کنید یا Managed certificate بگذارید. |
| قالب آپلودی به نود نمی‌رسد | پنل باید `REBECCA_PUBLIC_URL` قابل‌استفاده داشته باشد و نود با گواهی خودش Enroll شده باشد تا Archive را دریافت کند. |
| دانلود TemplateMo ناموفق است | دسترسی HTTPS خروجی نود و شکل لینک `/tm-NNN-name` روی سایت TemplateMo را بررسی کنید. |
| پیام HAProxy is not installed می‌آید | Rebecca Node را آپدیت یا دوباره نصب کنید. نصب باینری، آپدیت و Image داکر فعلی بسته را دارند. |
| پورت درحال استفاده است | Process فعلی روی آن آدرس و پورت را متوقف یا جابه‌جا کنید. همچنین هیچ اینباند Xray انتخاب‌شده‌ای نباید روی پورت عمومی Listener باشد. |
| Route روی یک نود کار می‌کند ولی Clone نود دیگر Skip می‌شود | نود مقصد باید همان Tag و Matcher دقیق را داشته باشد. اینباند را روی مقصد بسازید یا فعال کنید و دوباره Clone بزنید. |
| کلاینت کند به Backend اشتباه می‌رود | **زمان تشخیص** را با احتیاط بیشتر کنید و ببینید کلاینت SNI یا Host یا Path مورد انتظار را واقعاً می‌فرستد. |
| اتصال بعد از یک ساعت قطع می‌شود | Timeout کلاینت و سرور را بررسی کنید. Tunnel طولانی ممکن است به عددی بیشتر از پیش‌فرض `3600` ثانیه نیاز داشته باشد. |

برای خطاهای سمت نود، Log سرویس Rebecca Node را بخوانید. خطاهای Validation کانفیگ، نصب نبودن Package، دانلود قالب، گواهی و Bind پورت در همان Log نوشته می‌شوند. فقط وقتی Log معمول اطلاعات کافی ندارد، سطح `debug` را موقتاً فعال کنید.

## چک‌لیست نهایی

- تمام Targetها فعال هستند و فقط عضو همین Configuration هستند.
- پیش از اجرای HAProxy، آدرس و پورت عمومی روی هر نود آزاد است.
- پورت Backend هر اینباند Xray با پورت عمومی فرق دارد.
- SNI و Host و Path داخل هر Listener یکتا هستند.
- هر Listener فقط یک fallback دارد: یک Route از نوع Default یا اولین Website پیش‌فرض.
- Hostname وب‌سایت TLS با SNI هیچ Routeای تداخل ندارد.
- گواهی Managed فعال است و Hostname سایت را پوشش می‌دهد.
- مسیرهای Custom certificate روی تمام نودهای مربوط وجود دارند.
- خروجی Editor روی هر Target با Routeهای مورد انتظار یکسان است.
- بعد از Save، هر نوع ترافیک به‌صورت مستقل تست شده است.
